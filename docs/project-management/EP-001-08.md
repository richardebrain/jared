## Task Description
Implement the core intelligent question selection algorithm that drives the adaptive assessment experience with weighted domain distribution, 6-level difficulty progression, comprehensive fallback strategies, and automatic timer-driven progression to ensure assessments always complete regardless of frontend connectivity.

## Requirements

### Core Algorithm Requirements
- **Weighted Domain Selection**: Calculate target allocation, track progress, prioritize under-represented domains
- **6-Level Adaptive Difficulty**: Start at Medium (3), adjust ±1 based on correctness, maintain bounds (1-6)
- **Backend Timer Management**: Server-side timers with automatic question progression
- **Frontend Synchronization Recovery**: Handle out-of-sync scenarios with state recovery
- **Dual-Level Availability**: Platform and school-level question availability controls
- **Question Pool Management**: Pre-filter by availability, validate approval status, optimize performance
- **Comprehensive Fallback Strategy**: Adjacent difficulty (±1), cross-domain, any available - never fail
- **Performance Requirements**: <2 seconds selection time, 50+ concurrent selections, optimized caching

### Detailed Algorithm Specifications

#### Weighted Domain Selection Algorithm
```typescript
interface DomainAllocation {
  domainId: number;
  weight: number;           // From assessmentDomains.weight
  targetQuestions: number;  // Calculated from weight proportion
  currentQuestions: number; // Questions asked so far
  priority: number;         // Calculated urgency score
}
```

#### 6-Level Difficulty Progression
- **Level 1**: Easy (5 points) - Basic knowledge, recall-based questions
- **Level 2**: Easy/Medium (8 points) - Simple application scenarios  
- **Level 3**: Medium (10 points) - Standard professional situations
- **Level 4**: Medium/Hard (13 points) - Complex problem-solving
- **Level 5**: Hard (15 points) - Advanced analysis and synthesis
- **Level 6**: Master (20 points) - Expert-level professional judgment

#### Server-Authoritative Timer System
- Backend maintains authoritative time remaining for each question
- Frontend synchronizes with backend timer every 10 seconds
- Automatic progression occurs server-side when timer expires
- Recovery mechanisms handle frontend disconnection scenarios

#### 5-Level Fallback Strategy
1. **Exact Match**: Domain + Difficulty + Available
2. **Adjacent Difficulty**: Domain + (Difficulty ±1) + Available  
3. **Cross-Domain Same Difficulty**: Any Domain + Difficulty + Available
4. **Cross-Domain Adjacent**: Any Domain + (Difficulty ±1) + Available
5. **Any Available**: Any Domain + Any Difficulty + Available
